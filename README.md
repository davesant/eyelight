# minisearch

A drop-in, type-anywhere search component for any website. As you type, it highlights matches on the current page and suggests other pages on the same site. It needs no framework and works on static sites.

- **Live demo and docs:** https://davesant.github.io/minisearch/
- **Spec:** [SPEC.md](SPEC.md). **Requirement check:** [VERIFICATION.md](VERIFICATION.md)
- **First user:** [miniharp.dev](https://miniharp.dev)

## Use it

```html
<script src="https://cdn.jsdelivr.net/gh/davesant/minisearch@main/dist/minisearch.min.js"
        defer data-prompt="type to search"></script>
```

For page suggestions, build an index after your site builds:

```sh
npx -p @davesant/minisearch minisearch-index ./public
```

If there's no index, Minisearch falls back to `sitemap.xml`, or to a list of pages you provide. All the options are documented at https://davesant.github.io/minisearch/configuration.html.

## Repo layout

| Path | What |
|---|---|
| `src/` | Component source (plain ES modules, no dependencies). The entry points are `auto.js` (script tag, auto-starts) and `esm.js` (bundlers). The core is `minisearch.js`, plus `pagetext.js` (in-page text index and matching), `data.js` (loading index, sitemap and inline pages), `suggest.js` (ranking), `fold.js` (case and accent folding) and `styles.js`. |
| `lib/build-index.js`, `bin/minisearch-index.js` | Index builder library and CLI (Node 18+, no dependencies). |
| `dist/` | Build output. Only `minisearch.min.js` (script tag) is committed, so jsDelivr can serve it from GitHub. `minisearch.js` (unminified) and `minisearch.esm.js` are built locally and at npm publish. |
| `docs/` | Documentation site and live demo, served by GitHub Pages from `main` / `/docs`. `docs/minisearch.min.js` and `docs/minisearch-index.json` are generated by `npm run build` and committed. |
| `test/unit/` | `node --test` unit tests (folding, ranking, CLI, theme contrast). |
| `test/e2e/` | Playwright tests, named by SPEC requirement ID. |
| `test/fixtures/site/` | Fixture pages used by the e2e tests. |
| `scripts/` | `build.js` (esbuild bundle, docs copy, docs index, 12 KB gzip budget) and `serve.js` (static server). |
| `ci/ci.yml` | GitHub Actions test workflow, waiting to be moved into `.github/workflows/`. |
| `SPEC.md`, `VERIFICATION.md`, `TASKS.md`, `AGENTS.md` | Spec, requirement-by-requirement evidence, open tasks, agent rules. |

## Develop

```sh
npm install
npm run build        # dist/ + docs copies + docs index, checks size budget
npm test             # build + unit + Playwright (Chromium desktop + touch phone)
ALL_BROWSERS=1 npx playwright test   # also Firefox and WebKit (as CI does)
npm run serve        # docs at http://localhost:8080/minisearch/
```

## Deploy and publish

- **Docs and demo:** GitHub Pages serves the `docs/` folder on `main` (Settings > Pages > Deploy from a branch > `main` / `/docs`). Only `docs/` is public, so the repo notes aren't deployed. Run `npm run build` before committing, so the docs copy of the script and the docs index are current.
- **CDN:** jsDelivr serves `dist/minisearch.min.js` straight from GitHub (`@main`, or a tag such as `@v0.1.0` once tagged).
- **npm:** `npm publish --access public` publishes `@davesant/minisearch`. `prepublishOnly` runs the tests first.
- **CI:** `ci/ci.yml` runs all tests in Chromium, Firefox and WebKit. It becomes active once it's moved to `.github/workflows/ci.yml` (see TASKS.md).
