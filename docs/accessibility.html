Accessibility

Minimarker is designed to meet WCAG 2.2 level AA, and to stay out of the way of assistive technology and of the host site.

Turning type-to-search off (WCAG 2.1.4)

Type-anywhere is a single-character keyboard shortcut, so users must be able to turn it off. The open search bar has a Type-to-search: on/off button, and the choice is remembered in the browser. With capture off, the idle hint becomes a plain "Search" button. Sites can also turn capture off for everyone with data-capture="false".

How each area is handled

AreaWhat Minimarker does
Screen readersThe search box is an ARIA combobox with a listbox of suggestions. Match and suggestion counts are announced through a polite live region. In browse mode, screen readers handle keys themselves, so they never reach the page. Highlights don't change the page's DOM (marker strokes are drawn in the component's own hidden overlay), so reading order and the accessibility tree are unchanged.
Browser find-in-pageShortcuts that use Ctrl or Cmd are never captured. / and ' are never taken from the page, so Firefox's Quick Find still works.
Input methods (IME)Composition keys are ignored. Once the box is open, typing goes into a real text input, so IME, dead keys, paste and undo all work normally.
Host keyboard shortcutsKeys the site has already handled with preventDefault() are ignored. Sites can also list keys in ignoreKeys. Keys typed in the search box don't reach the site's own shortcut handlers.
Form fields and widgetsNothing is captured in inputs, text areas, selects, editable content, interactive ARIA widgets (menus, grids, listboxes, sliders and so on), modal dialogs, or areas marked data-minimarker-nocapture.
Focus (2.1.2, 2.4.3, 2.4.7)Focus is never trapped. Tab only moves between matches when you're in in-page mode and there are matches, and the box shows how to leave (Esc). Closing returns focus to where it was. All controls have visible focus styles.
Focus not obscured (2.4.11)If the idle hint would cover the focused element, it fades out. When the search is open, focused page elements are scrolled clear of the bar.
Contrast (1.4.3, 1.4.11)The default light and dark themes meet 4.5:1 for text and 3:1 for borders and focus rings. Marker strokes are blended onto the page so text keeps at least 4.5:1 against them on typical light and dark pages. This is checked in the test suite. In Windows high contrast mode, system colours and the browser's own text cursor are used instead of the marker and block cursor.
Motion (2.2.2, 2.3.3)The idle cursor and the block text cursor blink for no more than five seconds, and not at all with reduced motion. Reduced motion also turns off smooth scrolling and fades.
Target size (2.5.8)Buttons are at least 24 px, and 44 px on touch screens.
Reflow and zoom (1.4.4, 1.4.10)Sizes are in rem. The bar fits in a 320 px wide viewport without horizontal scrolling.
Label in name (2.5.3)The idle hint's accessible name always contains its visible prompt text, so voice control users can say what they see.
Name, role, value (4.1.2)All buttons have accessible names. Toggles use aria-pressed, and suggestions use aria-selected and aria-activedescendant.

Testing

An automated end-to-end suite covers every requirement in the specification in desktop and touch profiles. It runs in Chromium locally, and the continuous integration setup adds Firefox and WebKit. Manual testing with NVDA, JAWS, VoiceOver and TalkBack is planned before version 1.0. Please report any barrier you find.
