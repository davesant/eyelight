Type anywhere to search

Eyelight is an open source search box that any website can add with one script tag. As you type, it marks matches on the page like a highlighter pen. Press Enter and it suggests other pages on the site. When you're done, it gets out of the way.

This page is the live demo. Start typing anywhere, for example harmonica, bend or install.

Use the arrow keys or Tab to move between matches on this page. Press Enter to see matching pages on the site, and Esc to go back or close. On a phone, tap the search button in the corner.

What it does

Type anywhere

Typing on any page sends the text to a search box at the bottom left of the screen. A blinking block cursor hints that you can.

Highlight on the page

From two characters, every match on the page is marked with a highlighter-pen stroke. It ignores case and accents, and never changes your HTML.

Suggest pages

Press Enter to see pages and sections from the same site. The data comes from a small static index.

Keyboard first

Move through matches with the arrow keys or Tab. Enter shows site pages and Esc steps back. Prefer suggestions as you type, a centred bar or a flat highlight? Each is an option.

Works on phones

On touch screens, a floating button opens the same search, with large buttons for moving between matches.

Accessible and polite

Built to WCAG 2.2 AA. Users can turn type-to-search off. It respects reduced motion and never traps focus.

Quick start

1. Add the script

Put this anywhere in your pages, for example just before </body>. It's deferred, about 13 KB gzipped, and does nothing until someone starts typing.

<script src="https://cdn.jsdelivr.net/gh/davesant/eyelight@main/dist/eyelight.min.js"
        defer data-prompt="type to search"></script>

You can also self-host dist/eyelight.min.js, or install it from npm as @davesant/eyelight and import { init } from '@davesant/eyelight'.

2. Build a search index (for page suggestions)

After your site builds, run the index tool over the output folder. It writes eyelight-index.json with each page's title, description, keywords and headings.

npx -p @davesant/eyelight eyelight-index ./public

No index? Eyelight falls back to your sitemap.xml, or you can list pages yourself. See Search data.

3. Optional: choose what's searched

<nav data-eyelight-ignore>…</nav>              <!-- not searched -->
<div data-eyelight-nocapture>…</div>         <!-- typing here isn't captured -->

By default, Eyelight searches the page's <main> element (or the whole body if there isn't one). Every option is listed on the Configuration page.

Keyboard reference

KeyIn-page matches (where search starts)Site pages
Any letter or numberOpens search, or adds to the search text
↓ ↑Next or previous matchMove through suggestions
→ ←Next or previous matchMove the text cursor
Tab Shift+TabNext or previous matchMove focus as normal
EnterShow matching site pages (Shift+Enter: previous match)Open the selected page, or the first one
EscClose search and remove the highlightsBack to in-page matches

With startMode: 'suggest', suggestions show as you type instead, Esc switches between the two, Enter moves to the next match, and a quick Esc Esc closes.

Keys are never captured when you're typing in a form field or editable area, when you use Ctrl, Alt or Cmd, or when the site has already handled the key. Space, / and ' are never taken from the page, so scrolling, buttons and Firefox's Quick Find keep working.

Light and dark

Eyelight follows the system colour scheme by default. Sites with their own theme switch can call Eyelight.setTheme(). Try it:

You can also change colours, corner radius, fonts and more with CSS custom properties. See the custom theme demo.

Browser support

Current versions of Chrome, Edge, Firefox and Safari. Marker strokes are drawn in an SVG overlay, so they work everywhere. The flat solid style uses the CSS Custom Highlight API; in older browsers without it, search, match counts and scrolling still work, but matches aren't painted. If the script fails to load, your site simply works as it did before.
