Type anywhere to search

Minisearch is an open source search box that any website can add with one script tag. As you type, it highlights matches on the page and suggests other pages on the site. When you're done, it gets out of the way.

This page is the live demo. Start typing anywhere, for example harmonica, bend or install.

Press Esc to jump between matches on this page, and press it twice quickly to close. On a phone, tap the search button in the corner.

What it does

Type anywhere

Typing on any page sends the text to a search box at the bottom of the screen. A blinking cursor hints that you can.

Highlight on the page

From two characters, every match on the page is highlighted. It ignores case and accents, and never changes your HTML.

Suggest pages

Pages and sections from the same site are suggested as you type. The data comes from a small static index.

Keyboard first

Move through matches with the arrow keys or Tab. Esc switches between page matches and site suggestions.

Works on phones

On touch screens, a floating button opens the same search, with large buttons for moving between matches.

Accessible and polite

Built to WCAG 2.2 AA. Users can turn type-to-search off. It respects reduced motion and never traps focus.

Quick start

1. Add the script

Put this anywhere in your pages, for example just before </body>. It's deferred, about 10 KB gzipped, and does nothing until someone starts typing.

<script src="https://cdn.jsdelivr.net/gh/davesant/minisearch@main/dist/minisearch.min.js"
        defer data-prompt="type to search"></script>

You can also self-host dist/minisearch.min.js, or install it from npm as @davesant/minisearch and import { init } from '@davesant/minisearch'.

2. Build a search index (for page suggestions)

After your site builds, run the index tool over the output folder. It writes minisearch-index.json with each page's title, description, keywords and headings.

npx -p @davesant/minisearch minisearch-index ./public

No index? Minisearch falls back to your sitemap.xml, or you can list pages yourself. See Search data.

3. Optional: choose what's searched

<nav data-minisearch-ignore>…</nav>              <!-- not searched -->
<div data-minisearch-nocapture>…</div>         <!-- typing here isn't captured -->

By default, Minisearch searches the page's <main> element (or the whole body if there isn't one). Every option is listed on the Configuration page.

Keyboard reference

KeySite suggestionsIn-page matches
Any letter or numberOpens search, or adds to the search text
↓ ↑Move through suggestionsNext or previous match
→ ←Move the text cursorNext or previous match
Tab Shift+TabMove focus as normalNext or previous match
EnterOpen the selected page, or go to page matchesNext match (Shift+Enter: previous)
EscSwitch to in-page matchesSwitch to site suggestions
Esc Esc (quickly)Close search and remove the highlights

Keys are never captured when you're typing in a form field or editable area, when you use Ctrl, Alt or Cmd, or when the site has already handled the key. Space, / and ' are never taken from the page, so scrolling, buttons and Firefox's Quick Find keep working.

Light and dark

Minisearch follows the system colour scheme by default. Sites with their own theme switch can call Minisearch.setTheme(). Try it:

You can also change colours, corner radius, fonts and more with CSS custom properties. See the custom theme demo.

Browser support

Current versions of Chrome, Edge, Firefox and Safari. Highlighting uses the CSS Custom Highlight API. In older browsers without it, search, match counts and scrolling still work, but matches aren't painted. If the script fails to load, your site simply works as it did before.
