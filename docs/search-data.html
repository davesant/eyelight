Search data

Highlighting on the current page needs no setup at all. Page suggestions need a list of your site's pages. Eyelight can get that list in three ways, and all of them work on static sites.

SourceQualitySetup
Build-time index (recommended)Titles, descriptions, keywords and headings. Sections with ids are suggested on their own.Run one command after each build.
sitemap.xml (automatic fallback)URLs only. Titles are made from the URL, e.g. /guide/getting-started/ becomes "Getting started".None, if you already have a sitemap.
Your own listWhatever you provide.Add pages to the config.

Eyelight tries the index first, and falls back to the sitemap if the index is missing. Your own list is always added on top. Nothing is downloaded until someone starts searching, so page loads aren't affected.

The index tool

npx -p @davesant/eyelight eyelight-index <folder> [options]

  --out, -o <file>   output file (default: <folder>/eyelight-index.json)
  --base <path>      URL prefix the folder is served from (default: /)
  --exclude <glob>   skip matching files, relative to folder (repeatable; default 404.html)
  --clean-urls       write /about instead of /about.html
  --levels 1,2,3     heading levels to index (default 1,2,3)

The tool reads every .html file in the folder, and folder/index.html becomes /folder/. For each page, it records:

  • the <title>
  • meta description and keywords
  • h1 to h3 headings, with their ids

It skips <nav>, <footer>, scripts and anything marked data-eyelight-ignore. It has no dependencies and needs Node 18 or later.

Leaving pages out

Pages with <meta name="robots" content="noindex"> or <meta name="eyelight" content="noindex"> are skipped.

With a static site generator

Run the tool after the build, over the output folder:

// package.json
"scripts": {
  "build": "eleventy && eyelight-index _site"          // Eleventy
  // "build": "hugo && eyelight-index public"            // Hugo
  // "build": "astro build && eyelight-index dist"       // Astro
  // "build": "jekyll build && eyelight-index _site"     // Jekyll
}

Or call it from code: import { buildIndex } from '@davesant/eyelight/build-index'.

Sites served from a sub-folder

If your site lives at example.com/docs/, pass --base /docs/ to the tool, and point the script at the index:

<script src="…/eyelight.min.js" defer data-index="/docs/eyelight-index.json"></script>

Index format

If you'd rather generate the file yourself, for example from a CMS, write JSON in this shape. Only url is required. Only same-origin URLs are used.

{
  "version": 1,
  "pages": [
    {
      "url": "/guide/tuning.html",
      "title": "Tuning your harmonica",
      "description": "How to tune reeds and keep them in tune",
      "keywords": ["reeds", "pitch"],
      "headings": [{ "text": "Flattening a reed", "id": "flatten", "level": 2 }]
    }
  ]
}

You can pass the same array inline as window.eyelightConfig = { pages: [...] }.

How suggestions are ranked

Each word you type has to match the start of a word in the page's title, keywords, headings, description or URL. Accents and case are ignored. Title matches count most, then keywords, headings, description and URL. A heading with an id is suggested as its own result only when the heading itself matches. At most two sections are shown per page.
